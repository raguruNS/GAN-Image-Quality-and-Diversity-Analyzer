# GAN Image Quality and Diversity Analyzer

A web-based diagnostic application built with **Streamlit, PyTorch, NumPy, Pillow, Pandas, and Matplotlib** to evaluate the visual quality, structural uniqueness, pairwise similarity, and diversity of images generated by Generative Adversarial Networks (GANs), without training a GAN from scratch.

## 🌟 Key Features

### 1. Pretrained GAN Model Inference

- **Progressive GAN (PGAN):** Support for compatible pretrained checkpoints, including texture or portrait generation where available.
- **Deep Convolutional GAN (DCGAN):** Support for a locally implemented generator architecture using latent noise vectors, transposed convolutions, and batch normalization.
- Generate a configurable number of synthetic images.
- Control random seeds for reproducible generation where supported.
- Detect CUDA availability and support CPU execution when compatible.

**Important:** Each model architecture and checkpoint must be implemented and tested before claiming it is supported. Reproducibility may vary across hardware and software environments.

### 2. Image Upload and Validation

- Upload multiple images in PNG, JPG, JPEG, WEBP, and BMP formats.
- Upload ZIP archives containing image files.
- Validate image files before analysis.
- Provide a demo sample batch when sample images are included in the project.

### 3. Pixel-Level Image Quality Diagnostics

- **Brightness:** Estimate mean luminance using the ITU-R 601-2 formula:

  \[
  Y=0.299R+0.587G+0.114B
  \]

- **Contrast:** Measure grayscale intensity variation using standard deviation.
- **Exposure analysis:** Estimate underexposed pixels below luminance 25 and overexposed pixels above luminance 230.
- **Spatial sharpness:** Estimate edge detail using the variance of a discrete Laplacian.
- **Gradient energy:** Estimate changes in image intensity across horizontal and vertical directions.

These are low-level image diagnostics, not complete measures of perceptual quality or realism.

### 4. Perceptual Similarity and Diversity

- **Exact duplicate detection:** Use SHA-256 hashes to identify byte-identical files.
- **Difference hashing (dHash):** Compare coarse image structure using 64-bit hashes.
- **Pairwise similarity:** Calculate similarity between image pairs.
- **Similarity heatmap:** Visualize relationships between samples.
- **Configurable threshold:** Flag potential near-duplicate pairs.
- **Automatic classification:** Report the sample set as:
  - Appearing Diverse
  - Showing Some Repetition
  - Highly Repetitive

The diversity classification is heuristic and does not prove GAN mode collapse.

### 5. Reports and Data Export

- Export per-image quality metrics as `gan_quality_metrics.csv`.
- Export pairwise similarity results as `gan_pairwise_similarity.csv`.
- Export the analysis summary as `gan_diversity_full_report.md`.
- Display charts, image comparisons, and a summary report in Streamlit.

## 🔬 Methodology and Formulations

### 1. Difference Hashing (dHash)

The dHash algorithm compares neighboring grayscale pixels.

1. Convert the image to grayscale.
2. Resize it to \(9 \times 8\) pixels for an \(8 \times 8\) difference grid.
3. Compare neighboring horizontal pixels.
4. Convert the comparisons into a 64-bit hash.

For images \(A\) and \(B\), define similarity as:

\[
S(A,B)=1-\frac{d_H(H_A,H_B)}{64}
\]

Where:

- \(H_A\) and \(H_B\) are the image hashes.
- \(d_H\) is their Hamming distance.
- Higher scores indicate greater structural similarity under dHash.

### 2. Discrete Laplacian Sharpness

The discrete Laplacian is calculated as:

\[
L[y,x]=I[y-1,x]+I[y+1,x]+I[y,x-1]+I[y,x+1]-4I[y,x]
\]

The sharpness estimate is:

\[
Q_{\text{sharpness}}=\operatorname{Var}(L)
\]

Higher values can indicate stronger edges, but image noise and complex textures can also increase this statistic.

### 3. Diversity Classification

A practical heuristic can combine:

- Unique perceptual-hash ratio.
- Mean pairwise similarity.
- Fraction of pairs exceeding the near-duplicate threshold.

Illustrative thresholds are:

| Assessment | Example heuristic |
|---|---|
| Highly Repetitive | Mean similarity at least 0.80, or uniqueness below 70% |
| Showing Some Repetition | Mean similarity from 0.68 to 0.80, or uniqueness from 70% to below 92% |
| Appearing Diverse | Uniqueness at least 92%, mean similarity below 0.68, and fewer than 5% near-duplicate pairs |

These thresholds are configurable examples, not scientifically validated universal boundaries. A production implementation should define how overlapping conditions are resolved and test the classification on representative datasets.

## ⚠️ Limitations

- Pixel statistics and Laplacian sharpness do not establish semantic realism.
- dHash can miss semantic similarities and can flag visually harmless differences.
- A diverse sample set can still contain poor-quality images.
- Repetitive samples may suggest limited diversity but do not prove mode collapse.
- Pretrained model availability depends on compatible repositories and downloadable weights.
- CPU generation can be slow for large models.
- Reproducibility is not always guaranteed across different hardware and library versions.

For more rigorous GAN evaluation, consider:

- **FID:** Fréchet Inception Distance.
- **KID:** Kernel Inception Distance.
- **Precision and recall:** Evaluate fidelity and coverage of generated distributions.
- **LPIPS:** Compare perceptual similarity using learned feature representations.

FID and KID generally require an appropriate real-image reference dataset and a compatible feature extractor.
